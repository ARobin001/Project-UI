# 明德AI知识操作系统｜界面规范

本规范对应可运行的中文界面原型，用于设计评审与前端实施。原型使用示例数据和本地交互状态，没有连接组织权限、文件处理、知识检索或AI服务；屏幕中的数量、人员、证据与处理结果不代表后端已经实现。

## 页面职责

| 页面 | 用户问题 | 视觉中心 |
| --- | --- | --- |
| 知识中心 | 我有哪些知识库？ | 知识库卡片 |
| 知识库工作空间 | 这个知识库里有什么资料？ | 搜索、分类与资料列表 |
| 资料详情 | 资料说了什么，AI理解的依据是什么？ | 原文、AI理解与证据 |
| AI整理中心 | 处理到哪里，哪些资料需要处理？ | 批次与任务状态 |
| 问明德AI | 如何基于当前知识范围完成工作？ | 问题、回答与引用 |

普通用户导航统一中文。API路径、数据库对象名和代码对象名保留工程原名。知识空间类型表达用途，权限由独立的操作能力决定。

## 基准与布局

桌面设计基准为1440 × 960。全局侧栏宽208px，顶栏高56px，页面左右内边距32px。知识中心采用三列卡片，间距20px。知识库内部分类栏宽192px，资料区与分类栏间距24px。

资料详情使用宽抽屉，并支持展开阅读。详情标题、状态、主要操作和页签固定，正文单独滚动。背景统一遮罩并停止交互；关闭后回到触发资料的入口，保留搜索、筛选及列表位置。

1080px以下知识中心变为两列。760px以下全局导航收起，分类改为横向可滚动入口；440px以下知识库卡片变为一列，资料行的文件状态和AI整理状态移到标题下面。窄屏减少次要信息，保留正文大小与双状态。

## 颜色

配色依据《明德 AI 认证界面图文与配色设计规范 V1.0》的品牌语义，知识模块沿用白色内容面、雾蓝层级、墨蓝文字和单一行动蓝。认证专用插画、双栏布局与面积比例不移植到知识模块。

| 用途 | 全局 Token | 色值 |
| --- | --- | --- |
| 内容表面 | `--md-surface` | `#FFFFFF` |
| 页面与内嵌背景 | `--md-canvas` | `#F8FBFE` |
| 选中与柔和层级 | `--md-soft` | `#EDF5FF` |
| 强浅底 | `--md-soft-strong` | `#DDECF9` |
| 标准／强调边框 | `--md-border` / `--md-border-strong` | `#D6E4F0` / `#AFCDE6` |
| 标题／正文 | `--md-text-1` / `--md-text-2` | `#17304F` / `#425A76` |
| 辅助文字 | `--md-text-3` | `#5F7085` |
| 默认／悬停／按下主操作 | `--md-action` / `--md-action-hover` / `--md-action-active` | `#176CF4` / `#0F5FDC` / `#0B4FB8` |
| 文字链接 | `--md-link` | `#1268B5` |
| 成功前景／背景 | `--md-success` / `--md-success-soft` | `#176B3A` / `#F4FBF6` |
| 警告前景／背景 | `--md-warning` / `--md-warning-soft` | `#8A5A13` / `#FFF8EB` |
| 错误前景／背景 | `--md-danger` / `--md-danger-soft` | `#9E2F2F` / `#FFF6F5` |
| 信息前景／背景 | `--md-info` / `--md-info-soft` | `#1268B5` / `#EDF5FF` |

辅助文字在规范建议的 `#68788D` 基础上略微加深，以适应知识模块的雾蓝背景并满足普通小字4.5:1对比要求。色值集中在 `src/design.css` 的全局 `--md-*` Token；组件引用语义变量，不维护独立原始色板。

蓝色表示品牌、操作、选中、焦点和明确的信息状态；绿、黄、红只表示业务状态。知识库类型、文件格式和成员头像采用统一中性色，不使用状态色装饰。原文定位采用浅蓝高亮，不把选中误画成黄色警告。安全阻止使用警告语义与明确文字，不使用紫色。

不使用紫色操作、紫色焦点环或彩色类型图标。卡片不使用大阴影和渐变背景；浮层保留轻量阴影。颜色与文字、图标共同表达状态。

## 字体与间距

字体优先使用系统中文无衬线字体，正文14px，行高1.6；阅读内容行高1.8–1.95。主标题28–30px、字重600，知识库名称16px、字重600，资料标题14px、字重600，摘要及元信息12px。

状态小标签使用11px并配合完整文字；文件类型图标内的短标识使用10–11px。它们是空间受限的辅助标识，不能替代正文或状态列标题。窄屏不继续缩小这些字号。

间距采用4px基准，主要使用8、12、16、20、24、32px。卡片圆角10px，按钮和输入框圆角7px。主控件高40–42px，资料行高80px，菜单与导航点击区域至少约40px高。

## 知识库卡片

卡片顺序固定为名称与类型、用途、资料与分类数量、负责人及成员数量、更新时间。默认只显示一个负责人头像；成员数使用文字表示，完整成员信息进入管理入口。

卡片主体打开知识库。收藏与更多菜单是独立点击区域，不能触发打开知识库。更多菜单的设置、成员管理和归档由服务端操作能力控制。当前原型只演示相应界面，不以类型或前端角色判断代替权限校验。

类型筛选与关系筛选分别设置：类型包含个人、机构、项目与专题、行业、专家；关系包含全部范围、我负责的、与我共享。两者可组合。收藏和最近使用入口改变实际结果集合与页面标题。

## 资料列表

完整桌面列表列宽为：复选框20px、资料标题至少240px、分类80px、文件状态92px、AI整理100px、更新时间104px、更多操作32px；列间距12px。

点击标题打开详情，不勾选资料。点击复选框进入批量选择，不打开详情。查看中的行使用轻背景与左侧标记；选中的行使用更明确的雾蓝背景，并出现批量操作条。

文件处理状态与AI整理状态独立展示。文件处理失败提供“重新处理”；AI整理失败提供“重新整理”。可检索资料即使AI整理失败，仍然保留原文、检索与问答入口。尚未可检索的资料不能通过前端动画宣称已经就绪。

上传规则由 `GET /api/v1/knowledge/assets/upload-policy` 驱动。上传成功只表示原文件上传完成；只有实际状态确认后才显示“可检索”。无可靠进度数据时使用阶段提示，不制作百分比。原型本地处理流程仅用于交互展示。

## 资料详情与证据

详情页签固定为概览、原文、AI理解、证据、版本、资料信息。主数据契约使用 `GET /api/v1/knowledge/assets/{asset_id}` 聚合返回；组件不独立请求多个对象接口后自行拼接资料。

证据分开显示原文来源、位置、提取方式和核验状态。“AI整理”“历史规则”是提取方式；“已核验”“待核验”是核验状态，两者不互相替代。已核验必须有可追溯记录，AI整理完成不能自动等同于核验完成。

不可靠的历史页码直接显示“原文位置：待核验”，保留“查看原文”，不提供猜测位置的高亮。可靠的页码或段落位置提供“定位原文”，与摘录同时呈现用于核验。所有证据卡片使用同样的信息和操作顺序。

版本页只展示已有记录，不展示未实现的比较、切换、回滚和恢复。资料ID、内容分片数量、文件哈希、模型及提示词版本等技术信息收进折叠区。

## 可访问性与状态

所有主要操作可用键盘完成，并有清晰焦点描边。模态面板管理焦点；关闭后恢复到触发入口。悬停不是发现操作的唯一方式；图标按钮具备中文可访问名称。尊重减少动态效果偏好。

加载使用与内容结构相符的骨架或明确等待提示；空数据与筛选无结果分别说明。提交中防止重复操作，失败在相关区域解释恢复方式。无依据回答使用中性提示，请求错误则提供重试。无权限不能泄露不可访问资料的摘要与引用。

## 开发边界与验收

知识空间接口、收藏、共享、归档、组织权限、鉴权原文和真实AI处理能力需要与服务端契约对接。本地保存、模拟上传、演示问答和处理计时不能作为这些能力已经完成的证据。原型中的证据核验标签与原文均为示例。

验收主流程：知识中心进入知识库 → 搜索资料 → 打开详情 → 查看证据 → 核验原文 → 基于资料提问 → 点击引用返回资料。每一步检查知识范围、返回位置、状态对应操作及失败恢复。发布前仍需完成服务端组织、知识空间、资料与对话的权限校验。
